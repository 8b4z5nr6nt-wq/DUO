# DUO

iPhone・iPad向けの個人用英語学習PWAの土台です。日本語UI・黒を基調にした表示で、問題・履歴・設定をIndexedDBに保存します。アカウント、学習データを送る外部API、自動同期はありません。DUO教材の例文・訳・単語は同梱していません。教材から読み取った内容は利用者が確認して登録してください。

## 開発・起動

Node.js 22.12以上（この環境では24.19.0）、npmを使用します。

```sh
cd /workspace/DUO
npm ci --cache /workspace/.npm-cache
npm run dev -- --port 5173
```

開発サーバーはHMR用で、Service Workerは登録しません。PWA・オフライン動作は必ず本番ビルドで確認します。

```sh
npm run build
npm run preview -- --port 4173 --strictPort
npm test
npm run test:e2e
```

E2Eはビルド済み `dist` を配信し、Chromiumでデスクトップ・スマートフォン・タブレットサイズを検証します。`/usr/bin/chromium` があれば自動で使用し、別の実行ファイルは `CHROMIUM_PATH` で指定できます。なければ `npx playwright install chromium` を実行してください。WebKitも実行する場合:

```sh
PLAYWRIGHT_BROWSERS_PATH=/workspace/.pw-browsers npx playwright install webkit
PLAYWRIGHT_BROWSERS_PATH=/workspace/.pw-browsers TEST_WEBKIT=1 npm run test:e2e
```

Linuxではブラウザのシステム依存パッケージが別途必要になる場合があります。ダウンロード先 `cdn.playwright.dev`（リダイレクト先を含む）のネットワーク許可が必要です。今回のクラウド環境ではダウンロードが403で拒否されたため、WebKit・Safari実機は未検証です。Chromiumの画面サイズ試験はSafariの互換性を保証するものではありません。

## 初回の使い方

1. 初回はオンラインでアプリを開きます。本番版で「オフライン準備完了」が出るまで待ちます。
2. 「データ」で1件ずつ登録、またはJSON/CSVをプレビューして登録します。「開発用の架空データを追加」は教材と無関係な4件を追加します。重複番号は追加しません。
3. 「学習」で例文／単語、英語→日本語／日本語→英語を選びます。セクション・例文番号・単語番号は `1-5,8` のように入力できます。空欄は全範囲、未登録範囲は対象外です。開始前に対象数を表示します。
4. 番号順／ランダム、全問／指定数、苦手／期限到来／お気に入り／要復習を選べます。苦手は選択方向の最新評価が「微妙」「覚えてない」の登録済み問題です。
5. 回答して正解候補と比較し、正誤と記憶を評価します。正誤と「覚えた・微妙・覚えてない」は独立です。英語の登録正解・別解との一致だけを自動判定し、意味の同一性を判断できない回答は「判断保留」を初期選択して自己判定に任せます。近いスペルは候補として知らせます。日本語も自己判定が基本で、登録別解を候補として表示します。
6. 「覚えてないとして記録し、その場で再挑戦」で前の回答を保存してやり直します。再挑戦が正解でも前の不正解履歴は残ります。スキップは未回答として「覚えてない」で保存します。
7. 詳細画面でお気に入り・要復習を設定できます。「記録」で7日間の学習量、3段階評価の割合、例文／単語を分けたセクション別進捗と全回答履歴を確認できます。
8. 定期的に「データ」でJSONバックアップをファイルに保存します。

学習量・1日の目標は回答回数（再挑戦・スキップを含む）で集計します。結果には異なる問題の件数も表示します。復習予定は問題の種類・番号・出題方向別に管理し、「覚えた」の連続評価で設定日数の最大8倍まで伸ばします。復習間隔の変更は次の評価から反映され、既存の予定を遡って変更しません。

タイマーは有効な学習時間だけを計測します。ヒントは設定秒数から答えの先頭を1文字ずつ表示し、時間切れで正解候補・評価へ進みます。アプリや学習画面を離れた場合は停止し、戻って「再開」を押すまで進みません。Enterで回答確認、Shift+Enterで改行。IME変換中のEnterは送信しません。回答確定・評価ごとに履歴を保存しますが、未評価の入力・現在の問題位置はメモリ上です。再読み込みやOSの強制終了で途中のセッションを再開する機能は未実装です。保存済み回答は残ります。

## iPhone・iPadとオフライン確認

SafariでHTTPS配信のURLを開き、初回読み込み後、共有ボタン →「ホーム画面に追加」を選びます（OSでメニュー位置が異なります）。ホーム画面から起動できます。Safari 16以降を想定していますが、実機受け入れ試験は今後必要です。

「オフライン準備完了」後に機内モードにし、アプリを開き直してください。ホーム・検索・学習・結果・進捗を表示し、回答を評価してからもう一度開き直して履歴が残ることを確認します。初回読み込みはオンライン必須です。開発サーバーではオフライン準備をしないので、`build` + `preview` またはHTTPS配信版を使ってください。

IndexedDBの容量不足・保存拒否は日本語で通知します。保存に失敗した操作は画面上の確定データにも反映しません。別タブが保存していた場合は上書きを拒否し再読み込みを案内します。Safariのサイトデータ削除、プライベートブラウズ、OSによる容量整理はデータ消失の原因になります。永続保存リクエストが拒否されても利用できますが、バックアップは必要です。Safariタブとホーム画面アプリで保存領域の扱いがOSにより異なる可能性があるため、利用する起動方法で確認してください。

## 登録形式

JSONは問題オブジェクトの配列、または `{ "items": [...] }` を取り込みます。例（すべて開発用の架空データ）:

```json
[
  {
    "kind": "word",
    "number": 1,
    "section": 1,
    "en": "moon garden",
    "ja": "月の庭",
    "aliasesEn": ["lunar garden"],
    "aliasesJa": ["月面の庭"],
    "partOfSpeech": "名詞（架空表現）",
    "otherMeanings": "宇宙の庭（補足例）",
    "notes": "開発用であり教材データではありません。",
    "synonyms": "lunar garden",
    "related": ["moon gardener（番号なし・出題対象外）"],
    "favorite": false,
    "review": false
  }
]
```

必須: `kind` (`sentence` / `word`)、1以上の整数 `number`・`section`、空でない `en`・`ja`。番号は種類ごとに一意で、例文1と単語1は別の問題です。品詞、その他の意味、説明、類義語、番号なし関連表現は補足表示のみ。番号付き見出し語・熟語だけを独立した `word` として登録します。判定候補は主要な `ja` と `aliasesJa`、英語は `en` と `aliasesEn` です。補足の意味を勝手に正解候補にはしません。

CSVはUTF-8、1行目が列名です。配列欄は `|` 区切り、カンマ・改行・引用符を含む欄はCSVの引用符規則を使用します。

```csv
kind,number,section,en,ja,aliasesJa,partOfSpeech,notes
word,1,1,moon garden,月の庭,月面の庭|月の庭,名詞,開発用の架空データ
sentence,1,1,My robot grows blue tomatoes.,私のロボットは青いトマトを育てます。,,,開発用の架空例文
```

取り込み前に内容を表示し、番号重複・必須項目不足・形式エラーが1件でもあれば登録しません。既存問題の更新は一覧の詳細から「編集」を使ってください。種類・番号は記録との関連を守るため編集できません。一括登録は10000件・ファイル10MBまでです。大規模データの性能最適化は未実装です。

## バックアップと復元

バックアップは `version: 1`、`items`、`records`、`sessions`、`settings` を含むJSONです。形式と履歴を検証し、プレビュー後に確定します。

- **追加統合**: 同じ種類・番号の問題と設定は端末側を優先。未登録問題を追加し、復習記録は更新日時が新しいもの、履歴は未登録IDだけ追加します。
- **完全復元**: 現在の全データをバックアップの内容で置換します。プレビュー画面の確認チェックが必要です。先に現在のバックアップを保存してください。

復元を確定すると途中の学習は終了します。保存はIndexedDBの1トランザクションで行うため、保存失敗で一部だけ置き換わることはありません。バックアップに回答内容が含まれるため、ご自身で保管してください。復元ファイル上限は20MBです。

## GitHub Pages公開の準備（まだWeb公開していません）

`.github/workflows/pages.yml` を用意しています。**GitHub Actions画面から手動実行した場合だけ公開**します。pushだけでは公開されません。依存関係をロックファイルで導入し、単体テスト・ビルド・`/DUO/` でのオフライン機能検証が成功した後、`dist/` をPagesへ配信します。学習データをアップロードする処理はありません。

### 初回公開の手順

1. この作業で作成したアプリ全体と `.github/workflows/pages.yml` をコミットし、GitHubリポジトリ `8b4z5nr6nt-wq/DUO` の `main` にpushします。`node_modules/`・`dist/`・テスト結果は `.gitignore` で除外します。
2. GitHubでリポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。Pagesを利用できる権限・プランが必要です。非公開リポジトリでPages項目が使えない場合は、契約プランの対応を確認してください。
3. **Actions → Publish DUO to GitHub Pages → Run workflow** で `main` を選んで実行します。これが実際の公開操作です。
4. `build` と `deploy` の成功を確認します。`github-pages` の環境設定に承認ルールがある場合は、そのルールに従ってください。
5. 実行結果に表示されるPagesのURLをSafariで開きます。通常の想定URLは `https://8b4z5nr6nt-wq.github.io/DUO/` です。公開前のURLなので、現在アクセスできるとは限りません。
6. 「オフライン準備完了」後、架空データで検索・学習・記録保存を確認し、「ホーム画面に追加」します。機内モードで開き直し、同じ動作と履歴の保持を確認します。

GitHub Actionsには組み込みの `GITHUB_TOKEN` を使います。新しい個人アクセストークンやAPIキーの設定は不要です。ソース読み取り権限と、公開ジョブだけのPages書き込み・OIDC権限を設定しています。GitHub上での実行・公開は、この準備作業では行っていません。

### ローカルでPages用ビルドを確認

```sh
npm ci
npm run build
npm test
npm run test:pages
```

`test:pages` はビルド済みのファイルを `/DUO/` 配下だけで配信し、相対パス、PWAの起動URL・スコープ、Service Worker配置、通信切断後の再読み込み・検索・学習・履歴保存をChromiumで確認します。ブラウザの導入方法は上の開発手順を参照してください。通常のブラウザ試験は `npm run test:e2e` です。

### 更新・配信の注意

コードの更新を `main` にpushした後、同じワークフローを手動実行して再配信します。変更するたびに自動公開する設定にはしていません。相対パス設定なので、GitHub Pagesの `/DUO/` 配下で配信できます。画面遷移はハッシュURLを使い、Pages側のSPAルーティング設定は不要です。

Service WorkerにはHTTPSが必要です（localhostは開発例外）。PagesはHTTPSで配信します。ビルドごとにキャッシュ識別子を変更し、ユーザーのIndexedDBはアプリ更新で消しません。更新後はオンラインで開き、必要なら再読み込みしてからオフライン利用してください。GitHub Pagesのキャッシュヘッダーはこのリポジトリから個別に設定しません。

URL・ドメインが変わると保存領域も変わる場合があります。移行前にJSONバックアップを保存して、移行先で復元してください。クラウド開発環境の公開と、GitHub PagesでのWeb公開は別の操作です。外部API・サーバー側DBは不要です。
